Módulos

Todo lo que necesitas, integrado

Cada módulo está diseñado para funcionar sin configuración extra. Activa lo que necesitas en ass.toml.

🔀

Proxy inverso de alto rendimiento

Motor HTTP/1.1 y HTTP/2 nativo con hyper + tokio. Enrutamiento por dominio, subdominio y wildcard (*.app.com). Servido de archivos estáticos con soporte SPA.

  • Enrutamiento por dominio exacto o wildcard
  • Cabeceras X-Forwarded-* automáticas
  • Archivos estáticos con fallback SPA
  • Socket Unix como destino de proxy
🔐

TLS automático

Cliente ACME integrado. Emite y renueva certificados de Let's Encrypt o ZeroSSL sin intervención manual. Renovación automática 30 días antes de expirar.

  • ACME HTTP-01 nativo
  • SNI dinámico multi-dominio
  • Renovación automática
  • Redirect HTTP → HTTPS
⚙️

Gestión de procesos

Supervisor integrado con reinicio automático ante fallos, límite de reintentos configurable y logs rotativos por app. Equivale a PM2 o Supervisor.

  • Reinicio automático en fallos
  • Señales stop / restart / reload (SIGHUP)
  • Logs por app con rotación diaria
  • Variables de entorno por proceso
🔨

Build engine

Git clone/pull automático + ejecución de comandos de build. Detecta cambios en el repositorio y reconstruye + reinicia la app sin intervención humana.

  • git clone + pull automático
  • Cualquier comando de build
  • Auto-rebuild en nuevos commits
  • Poll interval configurable
🛡️

Firewall de aplicación

Filtrado de IPs con CIDR, rate limiting por IP, bloqueo de requests sin Host header y límite de tamaño de body. Headers de seguridad automáticos (HSTS, CSP…).

  • Allowlist / blocklist CIDR
  • Rate limiting por IP (req/seg)
  • Headers de seguridad automáticos
  • Límite de body configurable
🌐

Túneles NAT bypass

Expón servicios locales detrás de CGNAT o IP dinámica sin ngrok. Conexión WebSocket persistente hacia un servidor relay con reconexión automática.

  • WebSocket hacia relay propio
  • Reconexión con backoff exponencial
  • Soporte TCP / HTTP / HTTPS
  • Múltiples túneles simultáneos
🔄

Self-updater

El comando ss update descarga la nueva versión, verifica la firma criptográfica Ed25519 y reemplaza el ejecutable de forma atómica sin interrumpir los servicios activos.

  • Verificación Ed25519
  • Reemplazo atómico del binario
  • Backup automático antes de actualizar
  • Soporte multi-canal (stable/beta)
📄

Config unificada

Un único ass.toml o ass.json declara toda la infraestructura: rutas, apps, TLS, firewall, túneles y logging. Sin archivos dispersos.

  • TOML o JSON indistintamente
  • Validación al inicio
  • ss init genera el archivo de ejemplo
  • ss validate sin levantar servicios

Configuración

Un archivo, toda la infraestructura

Genera el archivo de ejemplo con ss init y personalízalo.

ass.toml 
# ─── Servidor ────────────────────────────
[server]
host = "0.0.0.0"
http_port = 80
https_port = 443
ssl_email = "admin@ejemplo.com"
force_https = true

# ─── App backend ─────────────────────────
[[app]]
name = "mi-api"
domain = "api.ejemplo.com"
repo = "https://github.com/usuario/mi-api"
build = "go build -o app ./cmd"
exec = "./app"
port = 8080
auto_update = true
security_headers = true

[app.env]
DATABASE_URL = "postgres://localhost/mydb"
APP_ENV = "production"

# ─── Frontend estático ───────────────────
[[app]]
name = "frontend"
domain = "ejemplo.com"
domains = ["www.ejemplo.com"]

[[app.static_routes]]
prefix = "/"
dir = "/var/www/dist"
compress = true

# ─── Firewall ────────────────────────────
[firewall]
enabled = true
rate_limit_rps = 100
allowlist = ["10.0.0.0/8"]

# ─── Túnel opcional ──────────────────────
[tunnel]
enabled = false
relay_server = "relay.ejemplo.com:7000"
1

Genera la configuración

Ejecuta ss init para crear un ass.toml de ejemplo con todos los campos documentados.

2

Define tus apps

Cada bloque [[app]] declara un servicio: dominio, comando de build, proceso a supervisar y puerto.

3

Valida antes de arrancar

Usa ss validate para detectar errores de configuración sin levantar ningún servicio.

4

Arranca todo

ss start provisiona certificados TLS, compila tus apps y activa el proxy. Todo en un comando.

Producción

Como servicio del sistema

systemd (Linux) 
# /etc/systemd/system/ass.service
[Unit]
Description=AASS - App Service Server
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/local/bin/ass start --foreground
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5
User=root
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
Activar servicio
# Instalar y activar
sudo systemctl daemon-reload
sudo systemctl enable --now ss

# Verificar estado
systemctl status ss

# Ver logs en tiempo real
journalctl -u ss -f

# Recargar config sin reiniciar
systemctl reload ss
