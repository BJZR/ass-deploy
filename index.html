Módulos

Todo integrado, nada extra

Activa lo que necesitas en ass.toml. Cada módulo funciona sin configuración adicional.

Proxy inverso de alto rendimiento

Motor HTTP/1.1 nativo con hyper + tokio. Enrutamiento por dominio exacto o wildcard (*.app.com), servido de estáticos con fallback SPA y headers X-Forwarded automáticos.

  • Enrutamiento por dominio y wildcard
  • Archivos estáticos + fallback SPA
  • Timeout y pool de conexiones configurable
  • Socket Unix como destino

TLS automático

Cliente ACME integrado para Let's Encrypt y ZeroSSL. Emite y renueva sin intervención, SNI dinámico multi-dominio.

  • ACME HTTP-01 nativo
  • Renovación automática a 30 días
  • SNI dinámico sin reinicio
  • Redirect HTTP → HTTPS

Gestión de procesos

Supervisor integrado equivalente a PM2. Reinicio automático ante fallos, logs rotativos por app, señales stop / restart / reload.

  • Reinicio con backoff configurable
  • Logs por app con rotación diaria
  • Variables de entorno por proceso
  • SIGHUP para reload graceful

Build engine

Git clone/pull automático + cualquier comando de build. Detecta cambios en el repo y reconstruye sin intervención humana.

  • git clone + pull automático
  • Cualquier comando de build
  • Auto-rebuild en nuevos commits
  • Poll interval configurable

Firewall de aplicación

Filtrado CIDR, rate limiting por IP con governor, bloqueo de requests sin Host y límite de body. Headers de seguridad automáticos.

  • Allowlist / blocklist CIDR IPv4/IPv6
  • Rate limiting por IP (req/seg)
  • HSTS, CSP, X-Frame-Options
  • Límite de body configurable

Túneles NAT bypass

Expón servicios locales detrás de CGNAT o IP dinámica. WebSocket persistente hacia relay propio con reconexión automática.

  • WebSocket hacia relay propio
  • Reconexión con backoff exponencial
  • Soporte TCP / HTTP / HTTPS
  • Múltiples túneles simultáneos

Self-updater

ass update descarga la nueva versión, verifica la firma Ed25519 y reemplaza el ejecutable de forma atómica sin detener los servicios.

  • Verificación Ed25519
  • Reemplazo atómico del binario
  • Backup automático antes de actualizar
  • Canales stable / beta / nightly

Configuración unificada

Un solo ass.toml o ass.json declara toda la infraestructura. ass init genera el ejemplo, ass validate lo verifica.

  • TOML o JSON indistintamente
  • Validación al inicio con errores claros
  • Hot reload con ass reload
  • Múltiples apps en un archivo

Configuración

Un archivo, toda la infraestructura

Genera el ejemplo con ass init y personaliza lo que necesites.

ass.toml
# ── Servidor ────────────────────────────────
[server]
host = "0.0.0.0"
http_port  = 80
https_port = 443
ssl_email  = "admin@ejemplo.com"
force_https = true

# ── App backend ──────────────────────────────
[[app]]
name   = "mi-api"
domain = "api.ejemplo.com"
repo   = "https://github.com/usuario/mi-api"
build  = "go build -o app ./cmd"
exec   = "./app"
port   = 8080
auto_update      = true
security_headers = true

[app.env]
DATABASE_URL = "postgres://localhost/db"
APP_ENV      = "production"

# ── Frontend estático ────────────────────────
[[app]]
name    = "web"
domain  = "ejemplo.com"
domains = ["www.ejemplo.com"]

[[app.static_routes]]
prefix   = "/"
dir      = "/var/www/dist"
compress = true

# ── Firewall ─────────────────────────────────
[firewall]
enabled          = true
rate_limit_rps   = 100
rate_limit_burst = 200
allowlist = ["10.0.0.0/8"]

# ── Túnel (opcional) ─────────────────────────
[tunnel]
enabled      = false
relay_server = "relay.ejemplo.com:7000"
01

Genera la configuración

Ejecuta ass init para crear un ass.toml de ejemplo con todos los campos documentados.

02

Define tus apps

Cada bloque [[app]] declara un servicio: dominio, comando de build, proceso y puerto interno.

03

Valida antes de arrancar

Usa ass validate para detectar errores de configuración sin levantar ningún servicio.

04

Arranca todo con un comando

ass start provisiona TLS, compila tus apps y activa el proxy. Todo de una vez.

Producción

Como servicio del sistema

ASS se integra con cualquier sistema de init. Los paquetes .deb y .rpm instalan la unidad automáticamente.

/etc/systemd/system/ass.service 
[Unit]
Description=ASS - App Service Server
Documentation=https://tu-usuario.github.io/ass-deploy/
After=network-online.target
Wants=network-online.target

[Service]
ExecStart=/usr/local/bin/ass start --foreground
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5
User=root
LimitNOFILE=65536
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
Gestión del servicio 
# Activar y arrancar al inicio
sudo systemctl daemon-reload
sudo systemctl enable --now ass

# Estado
systemctl status ass

# Logs en tiempo real
journalctl -u ass -f

# Recargar config sin reiniciar
systemctl reload ass

# Ver logs de una app concreta
ass logs mi-api

✓ La unidad systemd se instala automáticamente al usar los paquetes .deb o .rpm.

/etc/sv/ass/run 
#!/bin/sh
# Servicio runit para ASS
# Distros: Void Linux, Artix (runit), Devuan

# Crear directorio de logs si no existe
mkdir -p /var/log/ass

exec /usr/local/bin/ass start --foreground \
  -c /etc/ass/ass.toml 2>&1
/etc/sv/ass/log/run 
#!/bin/sh
# Logger para runit (svlogd)
mkdir -p /var/log/ass
exec svlogd -tt /var/log/ass
Activar el servicio 
# Dar permisos de ejecución
chmod +x /etc/sv/ass/run
chmod +x /etc/sv/ass/log/run

# Enlazar para activar al arranque
ln -s /etc/sv/ass /var/service/ass

# Gestión manual
sv up ass       # iniciar
sv down ass     # detener
sv restart ass  # reiniciar
sv status ass   # estado
Recargar configuración 
# Enviar SIGHUP para reload graceful
kill -HUP $(cat /var/service/ass/supervise/pid)

# O usando ass directamente
ass reload

ℹ️ runit es el init de Void Linux y Artix (runit). Crea /etc/sv/ass/ con los archivos run y log/run antes de activar.

/etc/init.d/ass 
#!/sbin/openrc-run
# Servicio OpenRC para ASS
# Distros: Alpine Linux, Artix (OpenRC), Gentoo

name="ass"
description="ASS - App Service Server"
command="/usr/local/bin/ass"
command_args="start --foreground -c /etc/ass/ass.toml"
command_background=true
pidfile="/run/ass.pid"
output_log="/var/log/ass/stdout.log"
error_log="/var/log/ass/stderr.log"

depend() {
    need net
    after logger
}

start_pre() {
    mkdir -p /var/log/ass /etc/ass/certs /var/lib/ass
    checkpath --directory --owner root:root --mode 0750 /etc/ass/certs
}
Activar el servicio 
# Dar permisos de ejecución
chmod +x /etc/init.d/ass

# Añadir al nivel de arranque default
rc-update add ass default

# Gestión
rc-service ass start    # iniciar
rc-service ass stop     # detener
rc-service ass restart  # reiniciar
rc-service ass status   # estado

# Recargar configuración
rc-service ass reload   # envía SIGHUP

✓ OpenRC es el init por defecto en Alpine Linux y Gentoo. El script usa command_background=true para que OpenRC gestione el PID automáticamente.

/etc/s6/sv/ass/run 
#!/command/execlineb -P
# Servicio s6 para ASS
# Distros: Artix (s6), Chimera Linux, s6-overlay (Docker)

# Definir variables de entorno
importas -u HOME HOME
importas -u PATH PATH

# Ejecutar ASS en primer plano (s6 gestiona el proceso)
exec /usr/local/bin/ass start --foreground -c /etc/ass/ass.toml
/etc/s6/sv/ass/log/run 
#!/command/execlineb -P
# Logger s6 con s6-log
exec s6-log -d3 T /var/log/ass
/etc/s6/sv/ass/finish 
#!/bin/sh
# Se ejecuta cuando el proceso termina
# $1 = exit code, $2 = signal number
echo "ass terminó con código $1 (señal $2)" \
  >> /var/log/ass/finish.log
Activar y gestionar 
# Dar permisos
chmod +x /etc/s6/sv/ass/run
chmod +x /etc/s6/sv/ass/log/run

# Activar el servicio
s6-rc-bundle-update add default ass

# O enlazar directamente (s6-svscan)
ln -s /etc/s6/sv/ass /run/s6/service/ass

# Gestión con s6-rc
s6-rc -u change ass   # iniciar
s6-rc -d change ass   # detener
s6-svc -h /run/s6/service/ass  # SIGHUP (reload)

ℹ️ s6 es el init de Chimera Linux y se usa en contenedores con s6-overlay. Todos los scripts deben ser ejecutables. s6 nunca bifurca — ASS debe correr en primer plano (--foreground).

/etc/init/ass.conf 
# Servicio Upstart para ASS
# Distros: Ubuntu (≤14.04), algunas versiones de RHEL 6

description "ASS - App Service Server"
author      "ASS Project"

start on (local-filesystems and net-device-up IFACE!=lo)
stop on shutdown

respawn
respawn limit 10 5

setuid root
setgid root

env HOME=/root
env PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin

pre-start script
    mkdir -p /var/log/ass /var/lib/ass /etc/ass/certs
end script

exec /usr/local/bin/ass start --foreground -c /etc/ass/ass.toml

post-stop script
    echo "ass detenido en $(date)" >> /var/log/ass/upstart.log
end script
Gestión del servicio 
# Iniciar
sudo start ass

# Detener
sudo stop ass

# Reiniciar
sudo restart ass

# Estado
sudo status ass

# Recargar (SIGHUP)
sudo reload ass

# Ver logs
tail -f /var/log/upstart/ass.log

⚠️ Upstart está en desuso. Se usa principalmente en Ubuntu 14.04 LTS y sistemas legacy. Para instalaciones nuevas, prefiere systemd u OpenRC.

# Cargar el agente (inicio automático al login)

# Para servicio del sistema (todos los usuarios):
# sudo cp dev.BJZR.ass.plist /Library/LaunchDaemons/

# Ver estado
launchctl list | grep ass

# Descargar (desactivar al arranque)
launchctl unload ~/Library/LaunchAgents/dev.BJZR.ass.plist

ℹ️ En macOS usa LaunchAgents para servicios de usuario o LaunchDaemons para servicios del sistema (requiere sudo). El binario debe estar en /usr/local/bin/ass.
